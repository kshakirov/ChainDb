# ADR 0004: Гибридный асинхронный ввод-вывод (Параллельный мост: TCP + FIFO)

## Status
Accepted

## Context
Для обеспечения максимальной гибкости и производительности ChainDB под экстремальной нагрузкой, ядро СУБД не должно ограничиваться только сетевыми TCP-сокетами. Для локального межпроцессного взаимодействия (IPC) с фронтенд-серверами (например, Nginx) классический сетевой стек TCP вносит лишние накладные расходы на парсинг пакетов операционной системы.

## Decision
Реализовать параллельный гибридный слой ввода-вывода (I/O). Ядро базы данных при старте одновременно инициализирует два абстрактных файла-интерфейса:
1. Внешний сетевой TCP-сокет (через Си-интерфейс FFI к `libc`).
2. Локальный именованный канал (Named Pipe / FIFO-труба `bin/query.fifo`) средствами чистого Scheme.

Оба созданных дескриптора оборачиваются в высокоуровневые порты Scheme и параллельно отдаются под контроль системному циклу прерываний операционной системы через функцию `register-input-port`.

## Consequences
* **Плюсы**: Абсолютная гибкость. Nginx может спамить локальные команды напрямую в быструю FIFO-трубу без сетевых задержек, пока внешние клиенты идут по TCP. Архитектура ядра становится 100% UNIX-way («Всё есть файл»). Тестирование асинхронного ядра упрощается до записи эхо-строк в файл.
* **Минусы**: Требуется аккуратный контроль `unregister-input-port` на обоих портах во избежание дублирования триггеров ОС.
