# ADR 0004: Стратегия защиты ядра от голодания задач (Starvation)

## Status
Proposed (Бэклог / В планах)

## Context
В текущей реализации `ChainDB` очередь `*ready-queue*` является плоским FIFO-списком. Если тяжёлая команда (например, `SCAN`) делает `async-yield`, она уходит в самый хвост. При высокой боевой нагрузке фронтенд может непрерывно забивать хвост очереди тысячами новых быстрых запросов `GET`. В результате тяжёлая задача никогда не доползёт до начала очереди и будет «голодать» (Starvation), удерживая память стека.

## Proposed Decision
Перестроить Диспетчер на двухуровневую систему очередей:
1. `*active-queue*` (Очередь Стариков) — для задач, которые уже выполнялись и уступили дорогу. Высший приоритет.
2. `*incoming-queue*` (Очередь Новичков) — для новых входящих запросов из сети.

Диспетчер на каждом такте сначала полностью выгребает очередь «стариков», гарантируя завершение начатых транзакций, и только затем берёт задачи из входящей очереди.
