# ADR 0003: Модульная декомпозиция рантайма ChainDB

## Status
Accepted

## Context
Для предотвращения хаоса в коде и исключения утечек памяти нам необходимо разделить монолитный скелет ядра ChainDB на изолированные слои. Каждый компонент должен отвечать только за свою задачу.

## Decision
Декомпозировать СУБД на три независимых модуля стандарта R6RS/Chez Scheme:
1. `(chaindb dispatcher)` — Библиотека управления очередью готовых задач. Инкапсулирует векторы `*ready-queue*` и `*dispatcher-continuation*`.
2. `(chaindb commands)` — Домен бизнес-логики. Выполняет команды (`GET`, `SCAN`), реализует автоматическое квантование по счетчику (Time Slicing).
3. `main.sps` — Главная точка входа. Принимает сетевой запрос, оборачивает в задачу и запускает Event Loop.

## Consequences
* **Плюсы**: Идеальная чистота в главном файле. Компоненты изолированы, их легко тестировать на REPL по отдельности.
* **Минусы**: Требуется строгое описание экспорта/импорта функций через синтаксис `library`.
