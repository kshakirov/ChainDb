# ADR 0001: Использование Stackful-продолжений (call/cc) для планировщика

## Status
Accepted

## Context
Нам необходимо реализовать конкурентную обработку запросов к In-Memory хранилищу в одном потоке ОС. Классический подход (стейт-машины в стиле JS/Python) усложняет написание глубоко вложенной логики обхода индексов и требует ручной сборки состояния. Блокирующий ввод-вывод или долгие вычисления монополизируют ядро.

## Decision
Выбрана модель кооперативной многозадачности на базе Stackful-продолжений (`call/cc`) рантайма Chez Scheme. Тяжелые функции самостоятельно вызывают `yield` для передачи контроля диспетчеру.

## Consequences
* **Плюсы**: Код операций пишется линейно и просто. Заморозка контекста работает на любой глубине вложенности функций. Переключение контекста занимает $O(1)$.
* **Минусы**: Разработчик ядра обязан контролировать точки квантования (`yield`). Ошибка в коде может увести ядро в синхронный бесконечный цикл.
