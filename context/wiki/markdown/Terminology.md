# Термины ChainDb

Это живой словарь проекта. Здесь зафиксировано, что именно мы имеем в виду в коде и разговорах; определения будут уточняться вместе с архитектурой.

## Данные и ввод-вывод

**bytevector** — непрерывная последовательность байтов Chez Scheme. Не обычный Scheme-вектор и не «вектор векторов».

**read buffer** — заранее выделенный bytevector фиксированной ёмкости, куда системный `read` записывает очередную порцию данных.

**chunk** — фактически прочитанная часть read buffer длиной `bytes-read`. Нулевой хвост исходного буфера в chunk не входит.

**payload** — полная полезная последовательность байтов, поступившая от внешнего отправителя. Один payload может быть прочитан несколькими chunk-ами.

**accumulator** — состояние, в котором накапливаются прочитанные chunk-и до возврата единого результата.

**used** — число значимых байтов, уже находящихся в накопительном буфере.

**capacity** — полный выделенный размер накопительного буфера. `capacity` может быть больше `used`.

**FIFO / named pipe** — именованный POSIX-канал. Для ядра это поток байтов: границы отдельных вызовов `write` не являются надёжными границами задач протокола.

**file descriptor / fd** — целочисленный дескриптор открытого системного ресурса, передаваемый в `poll`, `read` и `close`.

**non-blocking I/O** — режим, в котором операция не должна останавливать единственный Scheme-поток в ожидании данных.

**poll** — системная проверка готовности fd. В текущем прототипе `timeout = 0` означает мгновенную проверку без ожидания.

**revents** — флаги фактически произошедших событий, записанные `poll` в структуру `pollfd`.

## Runtime и планирование

**task** — вычисление, представленное thunk-ом и готовое к запуску диспетчером.

**ready queue** — FIFO-очередь задач и сохранённых продолжений, которые могут выполняться прямо сейчас.

**dispatcher** — механизм, который извлекает следующий thunk из ready queue и передаёт ему управление.

**event loop** — повторяющийся цикл: выполнить готовую работу, проверить источники событий, разбудить ожидающие задачи, продолжить.

**continuation** — сохранённое представление оставшегося вычисления; точка, к которой можно вернуться позднее.

**spawn** — помещение нового task-thunk в ready queue.

**yield / async-yield** — добровольная передача управления диспетчеру с сохранением текущего continuation для последующего возобновления.

**wake-up** — перевод ожидающей задачи в ready queue после появления интересующего события ввода-вывода.

## Протокол и корректность

**framing** — правило выделения полных команд из потока байтов, например по разделителю или длине. Граница chunk-а не является framing-границей.

**contract** — явно заявленное поведение процедуры: допустимые входы, возвращаемое значение и существенные эффекты.

**witness / свидетельство** — тест, значение или построение, которое подтверждает конкретное свойство программы. Сила свидетельства ограничена тем свойством, которое оно действительно проверяет.
