## 1. Description & Context
In the `ChainDB` core engine, data is received via POSIX named pipes (FIFOs). To maintain high responsiveness, reading operations through the Chez Scheme Foreign Function Interface (FFI) must **never block the main Scheme thread**.

Recently, initial testing with large payloads revealed that multi-part read chunks were overwriting previously read data or leaking `#<void>` values due to improper tail expressions and buffer management in Scheme procedures.

This ticket covers the full implementation requirements for non-blocking pipe reads, chunk accumulation, exact bytevector slicing, and return value guarantees.

---

## 2. Requirements & Specification

### A. Non-Blocking Pipe Opening
- **Flag `2050` (`O_RDWR | O_NONBLOCK`):**  
  Must be passed to `open(path, flags)` via FFI.  
  - `O_RDWR` (`2`): Prevents `open` from blocking when no external process has opened the FIFO for writing.
  - `O_NONBLOCK` (`2048`): Ensures non-blocking I/O operations on the file descriptor.

### B. Safe Polling with `c-poll`
- Before executing `c-read`, query file descriptor status using `c-poll` with `timeout = 0` (instant check).
- Only invoke `c-read` if `poll` returns a positive count (`poll > 0`), indicating data is ready in the kernel buffer.

### C. Chunk Accumulation & Trimming
- **Dynamic Slicing:** Each `c-read` invocation populates a fixed buffer (e.g., 128 bytes). Since `bytes-read` may be less than the buffer capacity, slice exact bytes using `bytevector-copy!`:
  ```scheme
  (let ([chunk (make-bytevector bytes-read)])
    (bytevector-copy! read-buffer 0 chunk 0 bytes-read)
    ...)
  ```
- **Accumulator Pattern:** Prepend each sliced chunk to an accumulator list `(cons chunk acc)` for $O(1)$ complexity per read iteration.

### D. Reversal & Concatenation
- When polling returns `0` (or `bytes-read <= 0`), terminate the loop.
- Reverse the accumulator list and concatenate into a single contiguous `bytevector`:
  ```scheme
  (apply bytevector-append (reverse list-of-vectors))
  ```

### E. Return Value Integrity (Preventing `#<void>` Leaks)
- **Eliminate `when` for Value Returns:** Replace top-level `when` expressions with `if` statements so that non-matching branches return a valid empty bytevector `(make-bytevector 0)` rather than `#<void>`.
- **Ensure Final Expression:** Ensure side-effecting procedures like `display`, `format`, or `c-close` are not the terminal expression in branches that are expected to return bytevector data.
